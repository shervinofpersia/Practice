1. Executive Summary

Beethoshen (بتهوشِن) is an elite AI-driven musicology agent designed to reverse-engineer musical tracks into "raw musical DNA." The system utilizes multimodal capabilities to analyze audio files or perform web-grounded research on specific tracks. Its primary function is to generate high-precision assets—including chord progressions, instrumentations, and phonetically engineered lyrics—optimized for use in AI music generation platforms such as Suno and Udio.

The application targets professional audio engineers, music producers, and AI enthusiasts who require deep structural analysis of music rather than simple metadata retrieval. By bridging traditional music theory with modern generative AI prompts, Beethoshen serves as a translation layer between human musical intent and algorithmic generation.

2. System Architecture

The system is architected as a stateless web application leveraging the Gemini Pro 1.5 Multimodal model as the core reasoning engine.

2.1 Core Components

Component Technology Description
Inference Engine Gemini Pro 1.5 Handles multimodal inputs (audio/video/text) and executes complex music theory reasoning.
Research Module Google Search API Retrieves verified metadata, lyrics, and production credits to ground the AI's hallucinations.
Audio Processor FFmpeg / WebAudio Pre-processes uploaded files (.mp3, .wav, .m4a) for optimal token ingestion.
Prompt Synthesizer Custom Logic Formats analysis data into strict Suno/Udio compatible prompt structures.

3. Core Features & Requirements

3.1 Multimodal Audio Deep-Dive

The system must accept direct audio uploads and perform native listening analysis. This includes identifying:

  • Rhythmic Analysis: Exact BPM, time signature, and groove identification.
  • Harmonic Analysis: Key center detection, scale/mode identification, and functional harmony extraction.
  • Timbral Analysis: Instrumentation breakdown and mixing characteristics.
  • Vocal Analysis: Identification of vocal techniques, specifically including Persian "Tahrir" (تحریر) ornamentation.

3.2 Web-Grounded Research

For query-based inputs (non-audio uploads), the system actively searches for:

  • Verified Metadata (Artist, Year, Album).
  • Official Lyrics (to be cross-referenced with audio).
  • Guitar Tabs/Chord Charts (for harmonic verification).

3.3 Lyric Engineering (Persian Focus)

A critical feature is the phonetic engineering of Persian lyrics. The system must automatically apply:

  • Diacritics (اعراب‌گذاری): Mandatory َ ِ ُ ّ on ambiguous words to ensure correct AI pronunciation.
  • Structural Tags: [Intro], [Verse], [Chorus], [Bridge], [Drop], [Outro].
  • Rhythmic Punctuation: Use of commas for micro-pauses and periods for full rests.

4. API Integrations

4.1 Google AI Studio (Gemini API)

Endpoint: POST /v1beta/models/gemini-1.5-pro:generateContent

Configuration:

  • temperature: 0.3 (Strict adherence to facts, low creativity).
  • topK: 40
  • safetySettings: Adjusted to allow artistic content analysis.

4.2 Search Integration

Service: Google Custom Search JSON API

Scope: Restricted to music databases (Genius, Ultimate-Guitar, Spotify, Wikipedia, AllMusic).

5. Data Flow & Processing Pipeline

The application follows a linear processing pipeline designed to minimize hallucination.

  1. Input Ingestion: User provides Text Query OR Audio File.
  2. Context Gathering:
    • If Audio: Transcode to 16kHz mono (token optimization) -> Upload to Gemini -> Extract acoustic features.
    • If Text: Execute Google Search -> Scrape top 3 verified results -> Compile context.
  3. Analysis Phase (The "Beethoshen" Kernel):
    • Analyze Harmony/Rhythm.
    • Reconstruct Lyrics with phonetic notation.
    • Draft Prompt Strategy.
  4. Formatting: Convert raw analysis into the 4-part JSON/Markdown output structure (Persian).
  5. Output Delivery: Render final report to user.

6. Technical Specifications

Hard Requirement: Temperature must be set to 0.3 to ensure the "Musicologist" persona remains authoritative and accurate, minimizing creative drift in factual analysis.

6.1 System Constraints

  • Supported File Types: .mp3, .wav, .m4a, .mp4
  • Max Audio Length: 15 minutes (Chunking required for longer files)
  • Latency Budget: < 30 seconds for full analysis

7. Output Format Specifications

The system output must strictly follow the Persian schema defined below. The API response should be structured to populate these exact fields.

Section 1: The Musical DNA (شناسنامه فنی)

🧬 ۱. دی‌ان‌ای و شناسنامه فنی موسیقی
* سبک و زیرشاخه: [Genre/Sub-genre]
* تمپو: [BPM]
* کسر میزان و ریتم: [Time Signature]
* گام و مُد: [Key & Scale]
* توالی آکوردهای اصلی: [Chord Progression]
* سازبندی دقیق: [Instrumentation]
* آنالیز وکال و لحن: [Vocal Analysis]

Section 2: AI-Optimized Lyrics (لیریکس مهندسی‌شده)

Must include full diacritics and structural tags.

[Verse 1]
من از میانِ طوفان‌ها گذشتم،
(Vocal improvisation: ooh, aaah)

Section 3: Studio Prompts (پرامپت‌های استودیویی)

English prompts formatted for copy-pasting into Suno/Udio.

Section 4: Arrangement Map (نقشه تنظیم)

Timeline view of the track structure (Intro -> Verse -> Chorus).

8. User Interface Design

The UI should reflect a "Studio Control Center" aesthetic.

8.1 Layout Structure

  • Header: Waveform visualization (static or reactive to upload).
  • Input Zone: Large drag-and-drop area for audio, combined with a search bar.
  • Analysis Dashboard: A grid layout displaying the 4 output sections.
    • DNA Panel: Table view of technical stats.
    • Lyrics Panel: Monospace font text area for easy copying.
    • Prompts Panel: One-click "Copy" buttons for Suno/Udio prompts.

9. Quality Assurance & Testing

9.1 Testing Strategy

Test Type Methodology Success Criteria
Harmonic Accuracy Compare AI output against verified chord sheets of 50 benchmark songs. >90% Key detection accuracy.
Phonetic Compliance Review Persian lyric generation for correct diacritic placement. Zero missing diacritics on homographs.
Prompt Efficacy Feed generated prompts back into Suno and compare output genre to original. Generated audio matches target genre/vibe.

9.2 Error Handling

The system must gracefully handle:

  • Unclear Audio: "Analysis Confidence Low - Please provide higher quality audio."
  • Unknown Tracks: Fallback to pure audio analysis if metadata search fails.
  • Copyright Restrictions: Analyze structure without reproducing copyrighted audio samples.
